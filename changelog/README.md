# 变更记录规则

每个有意义的变更新增一份独立 Markdown 文件，同一轮相关修改可合并。项目级要求以根目录 `AGENTS.md` 为准。

## 文件命名

```text
YYYYMMDDHHmmss-大概功能.md
```

使用新加坡时间 `Asia/Singapore`（UTC+08:00），取实际记录时间，精确到秒。例如 `20261123120046-项目规范与功能基线.md`。名称描述主要功能，不含空格或 Windows 文件名禁用字符；同秒重名时重新获取实际时间。

按文件名可直接排序。不要回填虚构时间或覆盖历史记录；首次整理已有能力时注明“当前功能基线补录”，不要将记录时间当作各功能的开发或发布日期。

## 模板

```markdown
# 简短变更标题

- 记录时间：YYYY-MM-DD HH:mm:ss +08:00（Asia/Singapore）
- 类型：新增 / 修复 / 调整 / 文档 / 功能基线补录

## 变更说明

- 本次修改了什么，以及用户能观察到的行为。

## 涉及文件

- `相对项目根目录的路径`：作用。

## 验证

- 实际执行的命令、结果和覆盖范围。
- 未执行的浏览器或真实模型验证及原因。

## 限制与后续

- 剩余限制及相关 roadmap 项；没有新增限制时注明“无新增限制”。
```

记录可按变更规模缩短，但须保留以上信息。不要包含密钥、敏感网页内容或未经执行的测试结论。能力状态变化时同步根目录 `ROADMAP.md`，用法变化时同步 `docs/usage.md`。测试命令与数字只写在 changelog，不写进其他文档。
