# 上下文、记忆和技能

## 已实现

`prompts.js` 统一构建稳定系统指令与每轮输入。后台使用配置的语言和模型，每轮包含目标、最近操作、轮数与当前页。模型返回严格 JSON，工具行为由代码白名单决定。

支持在未结束任务中追加补充指令，模型收到原目标、按时间排序的补充指令和最近操作；较新用户纠正优先。任务完成或手动结束后发送才新建。时间线供查看，不等于完整聊天记录。仓库 AGENTS.md 只约束开发，插件不读取它。

已实现模型管理的临时记忆：每轮提供 memoryIndex（名称与更新时间），正文通过 memory_read 按需读取。memory_write 用 id 和 value 写入/覆盖，memory_delete 按 id 删除，memory_clear 清空当前站点；模型决定是否使用和何时清理。单条最多 2000 字符，最多 12 条、总序列化长度 8000 字符。容量满时返回工具反馈，由模型删除或压缩，不静默丢失旧记忆。

临时记忆独立于 taskId，按标签页和源隔离，不固定注入上一任务内容，也不递归复制历史。模型完结或手动结束保留笔记；用户清空、关闭标签页或会话结束清除。网页和笔记均为不可信数据，不能覆盖用户最新更正。模型只在工具成功后声称记忆已修改；这是提示词约束，不代表线上模型必定遵循。

用户可在侧边栏查看并清空；清空会让进行中的模型回复失效，移除工具读取结果，任务暂停后可继续。清空笔记不删除用户已发送的补充指令。清空/删除临时笔记同时移除可能含旧笔记的任务摘要；后续可重新整理。完整聊天历史、技能协议仍未实现。

## 任务内上下文压缩（已实现）

原目标和全部已接受的用户补充独立保留，补充序列化上限 12000 字符，超限明确拒绝。每轮新页面替换旧快照。稳定目标、指令、摘要正文、归档目录及追加的结果置于请求前部；变化的记忆目录、轮数、状态、条件、最后结果及页面置于后部。摘要更新时间不发给模型，不使用服务商专用缓存标记。

默认 contextTokens=100000、compressionThreshold=80，输出预留 2000 token。只有上下文达到 `(contextTokens-2000)*compressionThreshold/100` 才触发，不按条数或固定历史字符数触发。窗口配置范围 8192～262144，阈值 50～95%。接口 usage.prompt_tokens 为锚点，加上全请求估算值的前后差异；无 usage 时全量估算，ASCII 每 4 字符约 1 token，非 ASCII 每字符约 1 token。系统提示估算也计入，但消息封装、语言和 tokenizer 差异仍有误差，不能称为精确计量。

锚点仅匹配同一 endpoint/model/language/key 的 SHA-256 标识；配置改变或压缩、记忆清理后失效。接口缓存 token 仅用于展示，不从容量扣除。没有 usage 的请求不会沿用旧锚点。

保留至少最近 6 条结果，向前扩展至输入预算 20%；剩余旧结果和前摘要交给独立摘要请求。超长单条结果采用 2000 字符开头及 1000 字符结尾的带标记摘录，摘要看到归档指针，原文仍保存；摘要输入估算超过输入预算 90% 时暂停保留原记录。摘要五个字段各最多 5 条、每条 240 字符，总计最多 4000 字符。

同一 task 更新中保存 contextSummary、contextArchive 和裁剪后的 results；摘要失败不裁剪。contextArchive 含 id、from、to 和原始 results，总序列化最多 100 万字符；满后暂停。historyIndex 仅列目录，模型 history_read(id,value=offset) 每次取 4000 字符，返回 nextOffset。旧 ID 不得作为当前操作目标。归档不跨任务，替换/清空任务即删除；已被旧版本裁掉的内容不能恢复。

摘要请求计预算且可取消，停止/补充后迟到回复失效。压缩后设置 compactionGuard，若下一次上下文仍过阈值则暂停，不循环摘要；成功执行模型请求后解除。用户清空/模型删除记忆使摘要失效，并从归档与活动结果清理 memory_* 记录，避免按需读取恢复已清笔记。

侧栏显示摘要及上次 API 输入/缓存用量。线上模型是否充分保存关键事实、是否命中缓存仍待测；本版没有精确 tokenizer、模型主动整理动作、全聊天归档；全局偏好见下文。

## 网站长期记忆（已实现）

IndexedDB 的网站笔记独立于任务和临时记忆，按完整 origin 跨任务/标签页/重启共享。每轮 siteMemoryIndex 仅带 id、updatedAt、source，正文通过 site_memory_read(id) 取单条。site_memory_write(id,value) 写入/更新，site_memory_delete(id) 删除，site_memory_clear 清空本站。每次模型请求仍计一轮，工具执行由后台处理。提示词要求只保留稳定、有来源的经验和纠正，不能把网页或笔记当作更高优先级指令；线上模型的记忆质量未验证。

笔记删除/更新时旧摘要和读取缓存失效；跨标签页版本变化在下一轮重新观察，进行中模型回复在派发动作前核对版本。手动操作取消同站请求并暂停运行任务。并发写入在 IDB 事务内校验 expectedVersion，避免静默覆盖。用户可在设置页查看、编辑、删除、清空和导出，无自动临时记忆迁移或整段聊天持久化。存储及限制见 [存储](storage.md)。

## 双层长期记忆（已实现基础版本）

长期记忆分为网站与全局两种作用域。网站与全局笔记使用独立对象仓库；全局共享指扩展后台可跨网站、任务、标签页和浏览器重启按需使用，不代表网站脚本可以读取，也不包含云同步或跨设备共享。

| 作用域 | 保存内容 | 示例 | 当前状态 |
|---|---|---|---|
| 网站长期记忆 | 完整 origin 特有的术语、操作流程、限制和经核实经验 | 保存后等待指定区域出现成功反馈 | 已实现网站笔记，记忆质量仍需真实模型验证 |
| 全局长期记忆 | 用户明确的跨站偏好、工作习惯，以及适用范围清楚的通用经验 | 整理结果优先使用中文表格；日期采用 YYYY-MM-DD | 已实现；真实模型的记忆质量待验证 |

### 存储、工具与上下文

- 延续本机 IndexedDB，以独立 object store 或等效显式作用域区分网站与全局记录，不将全局记录伪装成某个 origin，不用 session/local 模拟长期数据库；保留已有网站笔记，不自动迁移其范围。
- 保留 site_memory_* 工具；全局使用独立 global_memory_read/write/delete/clear 工具。每轮仅提供两份目录，后台记录和校验各自版本，正文按需读取，目录、读取结果及写入均受明确容量限制，不静默裁剪。
- 全局笔记保存 id/text/source/createdAt/updatedAt，source 只表示 user/model，不代表验证。提示词要求在正文区分用户偏好与执行经验，注明来源、适用条件和验证情况；没有单独结构化分类或事实审核，单站经验不能自动提升为全局事实。用户明确要求跨站记住时按其意图记录，范围不清时保留本站或询问范围。
- 记忆仅作参考：当前用户指令优先，站点特有事实只在本站适用；冲突无法判定时说明或澄清。记忆不能覆盖工具与权限边界，不能替代当前网页证据。
- 全局正文仅由受信任后台管理并按需发给配置的模型，不返回内容脚本、不直接注入页面；禁止保存凭据、API 密钥、验证码、临时 DOM ID 或未经筛选的整段网页内容。

### 并发与用户管理

- 网站和全局分别维护版本，写入由 IDB 事务执行原子版本校验；模型请求前及动作派发前检查其依赖版本。模型写入全局笔记后使其他进行中请求失效，其他任务在下一轮按版本清理旧读取缓存与摘要；用户操作立即清理所有现存任务的相关上下文。
- 用户编辑、删除或清空全局记忆时，取消可能使用旧全局记忆的所有站点请求、轮换运行代次并暂停相关任务，防止迟到回复重新写回。等待与未确定操作仍遵守现有 deadline 和不重放规则。
- 设置页分别提供网站/全局的查看、编辑、删除、清空与导出，明确操作范围；清空全局不删除网站笔记或当前用户指令。旧摘要、归档读取结果不得恢复已删除内容。

### 本次验证

Node 模拟覆盖全局跨源目录/按需读取、用户修改跨站取消和迟到写入隔离、清理摘要/归档读取结果、保留等待期限及未知执行检查点、可信管理入口、设置页编辑与失败保留草稿。Edge 真实扩展与本机 stub 覆盖数据库 v1→v2 保留网站笔记、全局 CAS 冲突/容量失败回滚/预取消、模型读写、设置页查看编辑删除清空导出及浏览器进程重启保留。真实模型的记忆选择、事实质量和冲突处理未验证。

技能与长期记忆分开：记忆保存事实和偏好，技能保存可复用操作方法、适用条件和验证步骤；技能可标注本站或通用范围，但当前尚未实现技能协议。

## 其他目标设计（未实现）

1. 稳定指令：身份、工具和行为原则，与网页内容分开。
2. 任务上下文：目标、计划、进度摘要和最近操作。
3. 按需网页上下文：相关块、表单及必要区域，避免重复发送整页。
4. 站点技能：成功步骤、页面识别条件及易错点，按站点和目标加载。

先提供“保存为站点流程”，确认后持久化文本和工具步骤，不存任意脚本或临时 DOM ID，执行时重新定位。不引入向量库、市场或本地服务。事实记忆、偏好、技能、任务检查点分别保存。

参考：[Hermes 提示词组装](https://hermes-agent.nousresearch.com/docs/developer-guide/prompt-assembly)、[记忆](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)、[Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)。只借鉴职责划分，尚未实现完整技能协议。

普通响应可带 subgoals 增量维护公开任务里程碑；独立 taskPlan 随目标/指令进入模型上下文，不靠历史裁剪保留。完成声明必须经规划快照条件核对，旧计划始终是历史数据，用户新指令与当前证据优先；不保存私有推理，不把里程碑等同已学会技能。

记忆修改/清空同时使当前 taskPlan 失效，并移除当前结果、原始结果归档及检查点请求中的 subgoals 元数据，避免计划标题/证据继续作为模型上下文出现。全局影响各站任务，网站只影响同 origin，临时清空影响当前标签页；既有执行中检查点保护保留其操作/条件/deadline/派发状态，不因清理计划而重放。记忆变更工具本次请求也不重新附回旧 subgoals。此规则针对已知结构化计划字段，不承诺擦除所有历史自由文本或用户原指令。

跨站/成员切换的上下文隔离设计见 [任务站点集合与标签归属设计](task-scope-v3.md)（未实现）：新 origin 只装配其站点目录，旧笔记正文/站点摘要不自动共享，来源不明的旧计划重新规划；全局笔记独立沿用，不将单站经验自动提升到全局。
