# 通用网页 Agent V1 实施规划

日期：2026-11-23（Asia/Singapore）。状态：M1–M3 的基础协议与运行器已实现，并通过模拟及本机 stub 浏览器回归；线上模型、多网站及完整验收矩阵仍需验证。M4 已实现正文分段及控件分页/标签片段查找，批量操作尚未实现。下文保留设计与验收目标，当前接口以 [架构](architecture.md) 和 [工具文档](browser-tools.md) 为准。

## 1. 目标与交付范围

用户给出网页任务后，Agent 能观察、执行、等待、验证、恢复。无论是填写资料、搜索筛选、编辑内容、翻页整理还是处理弹窗，都使用同一套工具与结果协议。

V1 交付以下能力：

- 工具结果有统一结构，分清操作已发出、界面已变化、预期已满足及结果未知。
- 模型可以声明并检查预期结果，使用等待工具处理异步页面。
- 页面变化和连接丢失后先恢复观察，避免重复提交。
- 任务结束附上能核实的证据；未核实的部分如实说明。
- 侧边栏可看到正在等待什么、实际观察到了什么，以及暂停原因。

不在首版实现跨站/多标签页协作、iframe、视觉操作、富文本控件、长期技能学习。保留临时记忆、追加指令和停止；当前填写与点击统一自动执行，独立文章工具入口及专属配置已退役。

默认仍为 50 次模型请求，可设为 0 不限；本规划不改用户配置。等待/读取次数与模型轮数单独统计，不把内部轮询变成额外模型请求。

## 2. 当前差距

| 当前实现 | 通用化需要解决的问题 |
|---|---|
| 工具返回 message、navigation、verification、connection 等不同形状 | 运行器和模型不能稳定比较结果 |
| 主要通过完整快照是否变化判断进展 | 时钟、广告或无关文本变化不能证明操作成功 |
| 填写核对目标 value/checked | 缺少点击、搜索、筛选、保存等可复用验证条件 |
| DOM 引用失效后重读或暂停 | 缺少可解释的目标重新定位与歧义处理 |
| 页面跳转/忙碌时等待下一轮 | 缺少明确等待条件、截止时间和恢复次数 |
| done/pause 依靠模型选择 | 缺少完成条件、证据与未核实结果的区分 |
| 分组含 fieldset/role 和部分题目 CSS 特征 | 应以语义分组和布局上下文为主，业务类名仅作兼容 |

不能靠继续增加提示词，替代工具和运行器中的状态判断。

## 3. 一次通用操作的闭环

```text
观察当前页 → 选择工具与目标 → 声明预期 → 执行一次
      ↑                                   ↓
重新定位/重新规划 ← 分类恢复 ← 验证 ← 按条件等待
                                  ↓
                          继续任务 / 有证据地结束
```

模型负责选择目标与计划；代码负责参数校验、动作派发、条件求值、超时、隔离和恢复边界。网页、记忆和工具文本始终是数据。

## 4. 统一工具结果（V2 草案）

```json
{
  "version": 2,
  "operationId": "op-123",
  "documentId": "document-7",
  "status": "success",
  "dispatch": "sent",
  "scope": "ui",
  "code": "FIELD_MATCH",
  "observed": {"value": "Alice"},
  "evidence": [{"condition": "field_equals", "matched": true}],
  "recovery": "none",
  "message": "目标字段值与指定值一致"
}
```

| 字段 | 约定 |
|---|---|
| status | success、not_satisfied、pending、unknown、unsupported、error |
| dispatch | not_sent、sent、unknown；表示动作派发状态，不等于结果 |
| scope | dispatch、ui、page；区分派发、本地字段、页面反馈证据 |
| code | 稳定错误/结果代码，业务逻辑不能解析 message 文案 |
| observed | 白名单字段的实际值或变化，限制长度，不额外读取敏感区 |
| evidence | 条件、是否匹配及必要观察；限制条数和字符数 |
| recovery | none、wait、observe、relocate、replan、pause；是建议，运行器决定执行 |

关键语义：

- success 只表示当前工具的预期满足，不表示整个任务或服务端操作成功。
- not_satisfied 表示已明确观察到与预期不符；unknown 表示证据不足，两者不能混用。
- pending 表示仍在等待，不应立刻重做动作。
- TOOL_ERROR 与 PORT_DISCONNECTED 分开，权限缺失与元素失效分开。
- 兼容层将旧 message/navigation/verification/connection 转成新结构，迁移时不直接删除已有错误处理。

## 5. 通用目标与预期结果

### 5.1 观察与定位

第一阶段保留当前快照 ID，增加 documentId、snapshotId 和截断范围信息。元素记录 role、可访问名称、标签、状态、父分组和相邻标题；语义分组优先使用 fieldset/legend、ARIA 关系和表单结构。

重新定位只在当前授权文档内进行。用快照中的语义描述寻找唯一匹配；0 个匹配重新观察，多个匹配要求模型消歧，不直接选择第一个。不可跨文档重放旧 ID，不开放任意 CSS、JavaScript 或正则执行接口。

题目类名可以保留作旧版兼容，但不新增题型解析、题目专用动作或“自动刷到满分”的运行器规则。

### 5.2 首版验证条件

| 条件 | 场景与判断 |
|---|---|
| field_equals | 字段实际值等于指定值 |
| checked_equals | 单/多选或受支持开关状态相符 |
| selected_equals / expanded_equals | 显式 ARIA 选中/展开状态相符；缺失或非法状态为 unknown |
| element_visible | 指定区域/元素存在且可见 |
| element_absent | 在已完整观察的指定范围内不存在 |
| text_present | 已定位区域出现指定文本，限制文本长度 |
| url_changed | 相对操作前 URL 发生变化；只证明导航 |
| url_equals | URL 与显式给定目标相同，仍受原站点边界限制 |

条件只使用当前快照 ID 或经过唯一匹配的受限语义目标。不存在的目标不一定满足 element_absent：若范围被截断、文档已切换或无法访问，则结果应为 unknown。

单次预期最多 5 个条件，默认全部满足；先不实现任意嵌套布尔表达式。作用域必须明确，不以整页出现“成功”两个字就断言某项保存成功。

填写、勾选和选择由执行器自动生成值相符条件。点击可由模型指定页面反馈条件；没有条件时只返回派发/观察证据，不暗示点击成功。

### 5.3 模型工具

- observe：读取当前概况；第一阶段不扩展为完整页面爬取。
- act：沿用 click/fill/check/select/scroll，并附可选 expected。
- wait：等待条件，持久化 deadline，返回匹配、超时或未知。
- verify：检查条件，不修改页面。
- done / pause：完成或受阻，分别携带证据说明。
- memory_*：沿用临时记忆工具，不把旧笔记当作当前页面事实。

可继续使用非流式 OpenAI 兼容接口与严格 JSON；不要求模型服务必须支持原生 function calling。

## 6. 运行器与恢复

### 6.1 状态推进

保留现有 taskId、运行代次与任务状态，新增操作级 operationId，以及待验证条件、deadline、最近观察摘要、恢复次数。等待阶段每次 tick 只做短检查；建议单次检查不超过 1.5 秒，默认总等待 10 秒，首版最大 30 秒。

当前默认条件等待 10 秒、模型可指定 100–30000ms；加载/忙碌兜底 30 秒。每个 tick 做一次只读检查，不在 worker 内执行长轮询。worker 恢复继续使用原 deadline，停止、追加指令和用户清空记忆使旧等待失效。已加入假时钟及真实 worker 中断验证；不保证浏览器调度精确到毫秒。

### 6.2 恢复决策表

| 情况 | 下一步 | 禁止行为 |
|---|---|---|
| 页面加载中 / PAGE_BUSY | 在截止时间内继续等待、读取 | 再点一次按钮 |
| 快照或目标过期，确认动作未派发 | 观察 → 唯一匹配 → 重新规划 | 复用旧目标 ID |
| 点击回执丢失 | 检查新文档、验证预期 | 因无回执重复提交 |
| 新 DOM 替换了字段节点 | 唯一匹配后只读核对新字段 | 立即认定填写失败或直接补写 |
| 条件明确不满足 | 将实际值交给模型重新规划 | 无条件循环同一动作 |
| 权限不足 / 不支持控件 | 暂停并给出具体原因 | 当成普通网络错误重试 |
| 模型 API 临时失败 | 沿用有限重试与预算 | 重复执行上一网页动作 |
| 达到等待/恢复预算 | 保留进度并暂停说明 | 将未完成标为完成 |

首版对同一恢复事件最多允许两次重新观察/定位；页面等待另有 deadline；超过后暂停。是否重做填写也不能只按“fill 可重复”判断，因为字段事件可能触发自动保存。默认先验证，再让模型规划新动作。

重启恢复 executing 阶段时保留“不重放”的约束：能用持久化条件只读核对则先核对；仍无法判断就暂停。

## 7. 任务完成与临时记忆

任务可记录 completionChecks，区分已验证、未满足、未知。可执行条件不满足时不进入 completed，返回模型重新规划或暂停。开放式总结任务无法完全自动判真，可由模型回答，但应注明证据来源，不编造网站反馈。

临时记忆保持模型按需使用，不由每次操作自动写入全部页面。建议模型保存用户更正、已核实进度和未解决事项，并标注来源。当前用户指令优先；完成条件必须由新观察验证，不能拿旧笔记证明本次已完成。

## 8. 代码落点与迁移顺序

保持原生 JS，无新增构建、服务端、包依赖或浏览器权限。以下新增模块按阶段引入，不为了目录整齐一次拆完代码。

| 模块 | 迁移内容 |
|---|---|
| 新 `tool-protocol.js` | V2 schema 校验、状态/错误码、旧结果适配 |
| 新 `conditions.js` | 纯条件校验与求值；不访问模型 |
| `core.js` | 通用元素语义、字段执行、旧文章兼容 |
| `content.js` | documentId、快照、条件检查和短等待 |
| `browser-tools.js` | 传输、注入、连接恢复及结构化错误 |
| `runtime.js` | operation 检查点、等待/验证阶段、恢复决策与任务终态 |
| `task-store.js` | 记录版本升级与旧任务默认字段 |
| `prompts.js` | 工具能力描述和证据传递，不承担执行状态判断 |
| `sidepanel.*` | 展示预期、实际结果、等待时间和恢复原因 |

先将现有结果规范化而不改变行为，再启用条件求值，最后改运行器状态。兼容旧 session；无法恢复的旧 pending 重新观察，不直接执行。配置与临时记忆保留。

## 9. 里程碑与验收

### M1：统一结果与观测语义（先实施）

- V2 工具结果及旧返回兼容，覆盖所有当前网页动作和传输错误。
- 通用元素分组，快照带文档标识与截断信息。
- 现有模拟/浏览器回归无退化，运行器不再按中文 message 判断无进展。

验收：同样的错误不因文案变化改变恢复行为；回执丢失明确为 unknown，原动作派发次数保持 1。

### M2：等待与验证

- 支持上述有限条件，自动生成字段条件。
- wait/verify 工具、deadline 检查点和取消。
- 侧边栏展示预期及实际证据。

验收：延迟出现结果时不重复点击；字段 DOM 替换后可重新定位核对；虚假成功文字不能通过错误作用域的条件。

### M3：恢复与任务完成（V1 发布门槛）

- 恢复决策表、次数上限、无进展证据和任务 completionChecks。
- 完成/未完成/未知的结束说明，以及继续入口。
- worker 中断、补充指令、跨页、权限错误的端到端回归。

验收：下列场景必须使用同一组工具，不写网站/题目特例，不能靠提高步数掩盖失败。

| 通用场景 | 故障注入 | 预期 |
|---|---|---|
| 填写个人资料 | change 后值被网站还原 | 判为未满足，不能声称保存完成 |
| 搜索与筛选 | 列表延迟 3 秒更新 | 等待指定区域，不重发搜索 |
| 保存编辑 | 点击已被处理但回执丢失 | 只核对反馈，保存请求计数为 1 |
| 翻页阅读 | 全文档导航与同 URL DOM 替换 | 原任务继续，旧目标失效 |
| 弹窗处理 | 相同文案出现在多个区域 | 作用域消歧，不能任取一个 |
| 长表单 | 目标位于已截断部分 | 报 unknown，不能声称不存在 |
| 操作中停止/追加 | wait 或模型请求尚未结束 | 旧结果不覆盖新状态，不继续动作 |
| worker 被终止 | executing / waiting / verifying 阶段 | 不重放副作用，deadline 不延长 |

测试至少覆盖模拟条件求值、假时钟、真实 DOM 事件、完整导航及可计数的服务端操作 fixture。浏览器 stub 验证工具链，线上模型另做填写/检索/保存至少三类任务的人工观察；两类验证分开报告。

## 10. V1 之后

按最新用户优先级，剩余 V1 验收随功能迭代持续补充，不作为新功能硬门槛。M4 做按需局部读取、文本/元素分页及低影响操作的批量执行。批次中的点击、导航、提交独立处理；页面变化立即中断剩余批次，不把所有动作塞成一条不可核对指令。

随后再评估视觉、iframe、多标签页和长期技能。是否扩大范围取决于上述通用场景的实际稳定性，不按工具数量或“像某个 Agent”判断完成度。


## 当前优先级补充：页面工具成功率修复

2026-11-23 按用户要求，先交付容器四向滚动、视口优先控件/区域抽取与点击事件兼容，针对“看不到后续控件、滚错容器、自定义控件不响应”补通用回归。保留现有预算、运行中补充指令、检查点与结果核对。该补充不代表 M4 全文分区读取或批量操作完成，也不替代 M1–M3 多网站、真实模型验收。
